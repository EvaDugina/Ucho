# Functionality — Ухо

## brunelleschi_stage

- Стадия: POC B
- Последнее обновление: 2026-09-19

## functional

### Core

- Команды для доверенных: `/pebble`, `/ucho`, `/ask`, `/about`, `/leta`, `/help`,
  `/start`. Только владельцу доступны `/upload`, `/sea`, `/adduser`,
  `/removeuser`, `/users`.
- `/pebble` всегда отвечает ровно «Больно.» без вызова LLM.
- `/ask` предлагает десять тем или принимает затравку. Тема сохраняется только как
  metadata raw-события. После выбора темы кнопкой и отправки вопроса бот удаляет
  сообщение «Выбери тему:»; при сбое генерации меню остаётся для повтора.
- Обычный ответ и `/ucho` сначала попадают в `00_raw/sessions`, затем обновляют
  `01_mood` и добавляют pending-дельты в `02_personality`.
- Ответная `reaction` и представление `/about` обращаются к человеку от первого
  лица, без позиции стороннего комментатора. Внутренние personality-дельты и
  профиль остаются нейтральными выводами от третьего лица.
- `/ucho <текст>` всегда начинает новую сессию: текст сохраняется как свободная
  заметка без привязки к прежнему вопросу, а следующие сообщения продолжают
  новый контекст.
- Файлы raw-сессии и её Markdown-представления называются
  `YYYYMMDDTHHMMSS_<uuid>.jsonl` и `YYYYMMDDTHHMMSS_<uuid>.md`:
  метка времени стоит первой для сортировки в редакторе.
- `/about` под пользовательской блокировкой сводит только pending-дельты с текущим
  профилем, версионирует результат и отдельным LLM-вызовом формулирует пересказ.
  Следующим сообщением отправляет полный профиль: заголовки и метаданные
  форматируются для Telegram; текст длиннее лимита делится на читаемые части.
  Перед разделами обязателен YAML-блок «Регистр речи», «Тон речи», «Открытость»,
  «Переносимость провокаций». Дата и счётчик сообщений отсутствуют.
  Оценки относятся к наблюдаемой переписке; при недостатке данных —
  «недостаточно данных». Значения переносимости — «низкая», «средняя», «высокая».
- Recovery после рестарта повторно анализирует уже сохранённое raw-событие, не
  создавая дубль.
- Ежедневный вопрос, recovery, догон после рестарта и вечернее окно напоминаний
  работают только для пользователей, которые остаются в whitelist.
- Только владелец может загрузить книгу, открыть `/sea` и нажать книжные кнопки
  из старых сообщений. Для остальных команды скрыты и запрещены в обработчиках.
- `/upload` принимает EPUB, FB2, `.md`, `.markdown` и `.txt` до 20 МБ: как
  caption-команду или после десятиминутного ожидания документа.
- Обычный парсер без LLM извлекает название, автора, верхние главы, вложенные
  секции и абзацы. Книга хранится глобально как оригинал, нормализованный UTF-8
  текст, `structure.json` и metadata.
- SHA-256 нормализованного текста определяет дедупликацию новых книг.
- `/sea` показывает постраничный список, запускает вопрос только по выбранному
  дословному фрагменту одной верхней главы и позволяет включать или выключать
  книги в напоминаниях. В пустой библиотеке сообщение не содержит кнопок;
  указатель страниц появляется только при нескольких страницах. Только после
  выбора фрагмента LLM формирует вопрос.
- Книжное напоминание отправляет цитату с названием и автором. Следующий обычный
  текст без другой reply-цели один раз повышает score книги и запускает разговор.
- `/leta` удаляет личный raw, mood, personality, state и книжные предпочтения, но
  не общие книги и не данные других пользователей.

### Secondary

- Владелец управляет whitelist через `/adduser`, `/removeuser`, `/users`.
- Telegram message IDs сохраняются в typed session events для reply-resume.
- Если подходящих книг нет, reminder помечается завершённым без fallback-текста.

### Edge cases

- Неизвестная slash-команда отвечает ссылкой на `/help` и не анализируется.
- Команда и reply на другой вопрос не расходуют pending книжной цитаты.
- Pending цитаты истекает только после успешной отправки следующего daily-вопроса.
- Дубликат книги не перезаписывает исходник.
- EPUB с traversal, DTD/entity, повреждённым ZIP, чрезмерным числом файлов или
  распакованным объёмом отклоняется.
- EPUB 3 использует nav, EPUB 2 — NCX; без рабочего оглавления верхними главами
  становятся читаемые linear spine-документы.
- FB2 notes/comments, Markdown code blocks и служебные части EPUB не выбираются
  как цитаты.
- Книга без текущего структурного индекса скрыта из `/sea` и напоминаний до
  ручного восстановления индекса из сохранённого исходника.
- При ошибке синтеза `/about` pending-дельты и текущий профиль не меняются.
- Без новых дельт `/about` не создаёт новую версию, кроме однократного дополнения
  старого профиля без обязательных метаданных. При дополнении текст разделов сохраняется.
- Persona, лица, маски, настройка тона и сохранение оценок реплик отсутствуют.

### Out of scope

- Граф концептов, связи, противоречия, MOC, digest и доменные профили.
- Psychometrics, OCEAN, MBTI, DISC, PANAS, EmoLex, VAD и Dostoevsky.
- Поиск по полному тексту библиотеки, удаление и переименование книг.
- Публичная регистрация, роли кроме owner/trusted, web-интерфейс.

## nonfunctional

- Пользовательские данные разделены по `users/<uid>` через request-scoped
  `contextvar`.
- Данные пишутся в примонтированный каталог хоста без Git-коммитов и push.
- При старте без снимка за текущую неделю и еженедельно по расписанию создаётся
  проверяемая копия данных в отдельном каталоге хоста; хранятся последние
  четыре снимка всей папки, то есть не более четырёх копий каждого пользователя.
- `/leta` очищает активный каталог пользователя. Снимки удаляются ротацией;
  это ограничение явно указывается пользователю.
- Критичные JSON/Markdown-файлы заменяются атомарно.
- Все project scripts и тесты запускаются в Docker.
- Исключения не показывают stacktrace пользователю; технические подробности идут в
  stderr и `.ucho/log.md`.
- Нормализованный текст книги ограничен 60 МБ; ZIP не извлекается на диск.
- Структура книги, metadata и выбор фрагмента не вызывают LLM. Модель получает
  только уже выбранный фрагмент до 1200 символов и его положение в главе.
- `.env` и ключи не коммитятся и не читаются инструментами разработки.
- Профиль, mood, вопросы, книжные фрагменты и пользовательский текст передаются
  модели только как недоверенные fenced-данные, а не system-инструкции.

## accept

- Меню и router содержат ровно 12 разрешённых команд; удалённых handlers нет.
- Не-владелец не видит `/upload` и `/sea` в меню и `/help`; прямые команды,
  документ и старая кнопка `/sea` не запускают книжные действия.
- После нового ответа существуют session event, mood current/month event и
  валидные personality-дельты; каталогов `qna/notes/02_*/03_personality` нет.
- Ошибка LLM оставляет raw event и pending recovery-ссылку.
- `/about` создаёт одну версию на набор pending-дельт и не меняет статусы при сбое.
- EPUB, FB2, MD, Markdown и TXT проходят happy path; PDF отклоняется. Nav, NCX,
  spine fallback, вложенные секции, лимиты, traversal и дедуп покрыты тестами.
- Ни один выбранный фрагмент не пересекает верхнюю главу; raw/pending сохраняют
  chapter ID, заголовок, путь секций и source locator.
- Общие книги видны двум пользователям, а toggles/scores различаются.
- Вес лотереи равен `score - min_score + 1`; pending повышает score ровно один раз.
- В runtime нет вызовов Git для пользовательских данных.
- Снимок содержит raw, mood, personality, личное состояние и книги, исключает
  `.git`, локальные настройки редактора, ключи и незавершённые временные файлы;
  проверка хешей обнаруживает повреждение копии.
- Docker pytest, smoke, Ruff и Gitleaks проходят.
- Пользователь вне whitelist не получает recovery, daily или reminder.
